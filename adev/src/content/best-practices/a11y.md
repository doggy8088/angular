# Angular 的無障礙

網頁由廣泛的人群使用，包括那些有視覺或運動障礙的人。
有各種輔助技術，使這些群體更容易與基於 Web 的軟體應用程式互動。
此外，設計一個更易於訪問的應用程式通常會改善所有使用者的使用者體驗。

如需深入了解設計無障礙應用程式所涉及的問題和技術，請參閱 Google 的 web.dev [Learn Accessibility](https://web.dev/learn/accessibility/) 課程。

此頁面將探討設計對所有使用者都適用的 Angular 應用程式的最佳實務，包括倚賴輔助技術的使用者。

建構可存取的網路體驗通常包括設定 [可存取的豐富網際網路應用程式 (ARIA) 屬性](https://web.dev/learn/accessibility/aria-html/)，以提供語意意義，否則可能會遺失。
使用屬性繫結範本語法來控制與可存取性相關屬性的值。

在 Angular 中繫結至 ARIA 屬性時，您必須使用 `attr.` 前綴。ARIA 規範特別依賴 HTML 屬性，而非 DOM 元素的屬性。

<docs-code language="html">
&lt;!-- Use attr. when binding to an ARIA attribute --&gt;
&lt;button [attr.aria-label]="myActionLabel"&gt;&hellip;&lt;/button&gt;
</docs-code>

注意：此語法僅適用於屬性*繫結*。
靜態 ARIA 屬性不需要額外的語法。

<docs-code language="html">
&lt;!-- Static ARIA attributes require no extra syntax --&gt;
&lt;button aria-label="Save document"&gt;&hellip;&lt;/button&gt;
</docs-code>

HELPFUL: 根據慣例，HTML 屬性使用小寫名稱 \(`tabindex`\)，而屬性則使用 camelCase 名稱 \(`tabIndex`\)。

## Angular UI 元件

由 Angular 團隊維護的 [Angular Material](https://material.angular.io) 函式庫是一套可重複使用的 UI 元件，旨在完全無障礙。
[元件開發工具組 (CDK)](https://material.angular.io/cdk/categories) 包含 `a11y` 套件，可提供支援各種輔助功能領域的工具。
例如：

* `LiveAnnouncer` 用於使用 `aria-live` 區域向螢幕閱讀器使用者宣布訊息。
    有關 [aria-live 區域](https://www.w3.org/WAI/PF/aria-1.1/states_and_properties#aria-live) 的更多資訊，請參閱 W3C 文件。

* `cdkTrapFocus` 指令在元素內鎖定 Tab 鍵焦點。
    使用它來為模式對話框等元件建立可存取的體驗，其中必須限制焦點。

有關這些工具和其他工具的完整詳細資訊，請參閱 [Angular CDK 無障礙概觀](https://material.angular.io/cdk/a11y/overview)。

### 擴充原生元素

原生 HTML 元素擷取了若干個對可及性很重要的標準互動模式。
在撰寫 Angular 元件時，您應該盡可能直接重複使用這些原生元素，而不是重新實作受良好支援的行為。

例如，不要為新的按鈕種類建立自訂元素，而是建立一個元件，該元件使用具有原生 `<button>` 元素的屬性選取器。
這最常套用於 `<button>` 和 `<a>`，但也可以用於許多其他類型的元素。

您可以在 Angular Material 中看到此模式的範例：
[`MatButton`](https://github.com/angular/components/blob/main/src/material/button/button.ts#L33C3-L36C5)、[`MatTabNav`](https://github.com/angular/components/blob/main/src/material/tabs/tab-nav-bar/tab-nav-bar.ts#L62) 和 [`MatTable`](https://github.com/angular/components/blob/main/src/material/table/table.ts#L40)。

### 使用容器處理原生元素

有時使用適當的原生元素需要容器元素。
例如，原生 `<input>` 元素無法有子元素，因此任何自訂文字輸入元件都需要用額外的元素包裝 `<input>`。
僅在自訂元件的範本中包含 `<input>`，元件的使用者無法設定 `<input>` 元素的任意屬性和特性。
相反地，建立一個容器元件，使用內容投影將原生控制項包含在元件的 API 中。

您可以參閱 [`MatFormField`](https://material.angular.io/components/form-field/overview) 作為此模式的範例。

## 路由

### 導航後焦點管理

在 UI 中追蹤和控制 [焦點](https://web.dev/learn/accessibility/focus/) 是在為無障礙設計時的重要考量。
使用 Angular 路由時，您應該決定在導航時頁面焦點會移到哪裡。

為了避免僅依賴視覺提示，您需要確認您的路由程式碼在頁面導覽後更新焦點。
使用 `Router` 服務的 `NavigationEnd` 事件來了解何時更新焦點。

以下範例顯示如何在導覽後在 DOM 中找到並聚焦主要內容標題。

<docs-code language="typescript">

router.events.pipe(filter(e =&gt; e instanceof NavigationEnd)).subscribe(() =&gt; {
  const mainHeader = document.querySelector('&num;main-content-header')
  if (mainHeader) {
    mainHeader.focus();
  }
});

</docs-code>

在實際應用中，接收焦點的元素取決於您特定的應用結構和版面配置。
焦點元素應將使用者置於立即移至剛剛導向至檢視的主要內容的位置。
您應避免在路由變更後焦點返回至 `body` 元素的情況。

### 主動連結識別

應用於主動 `RouterLink` 元素的 CSS 類別，例如 `RouterLinkActive`，提供視覺提示以識別主動連結。
不幸的是，視覺提示無法幫助失明或視障人士。
將 `aria-current` 屬性應用於元素有助於識別主動連結。
如需更多資訊，請參閱 [Mozilla Developer Network (MDN) aria-current](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-current))。

`RouterLinkActive` 指令提供 `ariaCurrentWhenActive` 輸入，當連結變為活動狀態時，將 `aria-current` 設為指定值。

以下範例顯示如何將 `active-page` 類別套用至連結，並在其啟用時將其 `aria-current` 屬性設定為 `"page"`：

```html
    <nav>
      <a routerLink="home"
         routerLinkActive="active-page"
         ariaCurrentWhenActive="page">
        Home
      </a>
      <a routerLink="about"
         routerLinkActive="active-page"
         ariaCurrentWhenActive="page">
        About
      </a>
      <a routerLink="shop"
         routerLinkActive="active-page"
         ariaCurrentWhenActive="page">
        Shop
      </a>
    </nav>
```
