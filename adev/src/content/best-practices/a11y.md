# Angular 的無障礙設計

網路的使用者形形色色，其中也包括視覺或行動方面有障礙的人。
市面上有各種輔助技術，能讓這些族群更容易與以網路為基礎的軟體應用程式互動。
此外，把應用程式設計得更容易使用，通常也能改善所有使用者的整體體驗。

若想深入了解設計無障礙應用程式的議題與技巧，請參閱 Google 在 web.dev 上的 [Learn Accessibility](https://web.dev/learn/accessibility/) 課程。

本頁說明設計 Angular 應用程式的最佳實務，讓所有使用者（包括仰賴輔助技術的人）都能順暢使用。

## 無障礙屬性

<!-- TODO: add link once attribute binding guide is implemented -->
要打造無障礙的網路體驗，往往需要設定 [Accessible Rich Internet Applications（ARIA）屬性](https://web.dev/learn/accessibility/aria-html/)，在原本缺少語意的地方補上語意。
你可以用屬性繫結範本語法，控制與無障礙相關的屬性值。

在 Angular 中繫結 ARIA 屬性時，必須使用 `attr.` 前綴。ARIA 規格明確依賴 HTML 屬性，而不是 DOM 元素的 property。

<docs-code language="html">
<!-- Use attr. when binding to an ARIA attribute -->
<button [attr.aria-label]="myActionLabel">…</button>
</docs-code>

Note: 這種語法只有在屬性「繫結」時才需要。
靜態的 ARIA 屬性不需要額外語法。

<docs-code language="html">
<!-- Static ARIA attributes require no extra syntax -->
<button aria-label="Save document">…</button>
</docs-code>

HELPFUL: 依照慣例，HTML 屬性使用小寫名稱（`tabindex`），屬性（property）則使用 camelCase 名稱（`tabIndex`）。

## Angular UI 元件

由 Angular 團隊維護的 [Angular Material](https://material.angular.io) 程式庫，是一套可重複使用的 UI 元件，目標是做到完全無障礙。
[Component Development Kit（CDK）](https://material.angular.io/cdk/categories) 包含 `a11y` 套件，提供支援各個無障礙領域的工具。
例如：

* `LiveAnnouncer` 會利用 `aria-live` 區域，為螢幕閱讀器使用者播報訊息。
    更多關於 [aria-live 區域](https://www.w3.org/WAI/PF/aria-1.1/states_and_properties#aria-live) 的資訊，請參閱 W3C 文件。

* `cdkTrapFocus` 指令會把 Tab 鍵的焦點限制在某個元素內。
    你可以用它為模式對話框之類的元件打造無障礙體驗，這類元件必須限制焦點的移動範圍。

這些工具與其他工具的完整說明，請參閱 [Angular CDK 無障礙總覽](https://material.angular.io/cdk/a11y/overview)。

### 強化原生元素

原生 HTML 元素本身就具備幾個對無障礙很重要的標準互動模式。
撰寫 Angular 元件時，只要做得到，就應該直接重複使用這些原生元素，而不是重新實作已經有良好支援的行為。

例如，與其為新型態的按鈕建立自訂元素，不如建立一個使用屬性選擇器、搭配原生 `<button>` 元素的元件。
這最常用在 `<button>` 與 `<a>` 上，但也能用在許多其他類型的元素。

你可以在 Angular Material 裡看到這種模式的範例：
[`MatButton`](https://github.com/angular/components/blob/main/src/material/button/button.ts#L33C3-L36C5)、[`MatTabNav`](https://github.com/angular/components/blob/main/src/material/tabs/tab-nav-bar/tab-nav-bar.ts#L62) 與 [`MatTable`](https://github.com/angular/components/blob/main/src/material/table/table.ts#L40)。

### 用容器包裝原生元素

有時候，要使用合適的原生元素，就需要一個容器元素。
例如，原生 `<input>` 元素不能有子元素，所以任何自訂文字輸入元件都需要用額外元素把 `<input>` 包起來。
若只是把 `<input>` 放進自訂元件的範本裡，元件的使用者就無法對 `<input>` 元素設定任意的屬性與特性。
這種情況下，應該建立一個容器元件，利用內容投影把原生控制項納入元件的 API。

你可以把 [`MatFormField`](https://material.angular.io/components/form-field/overview) 當作這種模式的範例。

## 路由

### 導航後的焦點管理

在 UI 中追蹤並控制[焦點](https://web.dev/learn/accessibility/focus/)，是無障礙設計的重要考量。
使用 Angular 路由時，你應該決定頁面導航後焦點要移到哪裡。

為了避免只仰賴視覺提示，你需要確保路由程式碼在頁面導航後會更新焦點。
你可以用 `Router` 服務的 `NavigationEnd` 事件，掌握更新焦點的時機。

下面的範例示範導航後如何在 DOM 中找到主要內容的標題並把焦點移到它上面。

<docs-code language="typescript">

router.events.pipe(filter(e => e instanceof NavigationEnd)).subscribe(() => {
  const mainHeader = document.querySelector('#main-content-header')
  if (mainHeader) {
    mainHeader.focus();
  }
});

</docs-code>

在真實應用程式中，接收焦點的元素取決於你應用程式的具體結構與版面配置。
取得焦點的元素，應該讓使用者能立刻進入剛被路由帶進畫面的主要內容。
你應該避免路由切換後焦點回到 `body` 元素的情況。

### 使用中連結的標示 {#active-links-identification}

套用在作用中 `RouterLink` 元素上的 CSS 類別（例如 `RouterLinkActive`），會提供視覺提示來標示作用中的連結。
可惜的是，視覺提示對盲人或視障使用者沒有幫助。
把 `aria-current` 屬性套用到元素上，能協助標示作用中的連結。
更多資訊請參閱 [Mozilla Developer Network（MDN）的 aria-current](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-current))。

`RouterLinkActive` 指令提供 `ariaCurrentWhenActive` 輸入，當連結變成作用中時，會把 `aria-current` 設為指定的值。

下面的範例示範如何把 `active-page` 類別套用到作用中的連結，同時在連結作用中時把它的 `aria-current` 屬性設為 `"page"`：

```html
    <nav>
      <a routerLink="home"
         routerLinkActive="active-page"
         ariaCurrentWhenActive="page">
        Home
      </a>
      <a routerLink="about"
         routerLinkActive="active-page"
         ariaCurrentWhenActive="page">
        About
      </a>
      <a routerLink="shop"
         routerLinkActive="active-page"
         ariaCurrentWhenActive="page">
        Shop
      </a>
    </nav>
```
