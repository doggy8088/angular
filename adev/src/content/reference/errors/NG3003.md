# 循環匯入偵測

此元件、指令或管線被此元件參照，編譯器需要新增一個匯入，這將導致匯入迴圈。
例如，考慮一個 `ParentComponent` 在其範本中參照 `ChildComponent` 的場景：

<docs-code header="parent.component.ts" path="adev/src/content/examples/errors/cyclic-imports/parent.component.ts"/>

<docs-code header="child.component.ts" path="adev/src/content/examples/errors/cyclic-imports/child.component.ts"/>

由於 `ChildComponent` 在其建構函式中參照 `ParentComponent`，因此已經從 `child.component.ts` 匯入到 `parent.component.ts`。

HELPFUL：父組件的範本包含 `<child></child>`.
此範本的產生程式碼因此必須包含對 `ChildComponent` 類別的參考。
為了建立此參考，編譯器必須從 `parent.component.ts` 新增匯入至 `child.component.ts`，這將導致匯入循環：

<docs-code language="text">

parent.component.ts -&gt; child.component.ts -&gt; parent.component.ts

</docs-code>

## 遠程作用域

如果您使用 NgModules，為了避免新增會產生循環的匯入，會在宣告連結依賴項的組件的 `NgModule` 類別中新增額外的程式碼。

這被稱為「遠程作用域」。

## 函式庫

很遺憾，「遠端範圍」程式碼會產生副作用&mdash;這會阻礙 tree shaking&mdash;且無法在程式庫中使用。
因此，在使用 `"compilationMode": "partial"` 設定來建構程式庫時，任何需要循環匯入的元件都會導致這個 `NG3003` 編譯器錯誤被提出。

## 偵錯錯誤

產生的循環顯示為錯誤訊息的一部分。
例如：

<docs-code hideCopy="true">

The component ChildComponent is used in the template but importing it would create a cycle:
/parent.component.ts -&gt; /child.component.ts -&gt; /parent.component.ts

</docs-code>

使用這個來識別被引用的元件、管道或指令如何具有對正在編譯的元件的反向依賴。
以下是一些解決問題的想法：

* 嘗試重新排列您的依賴項以避免循環。
  例如，使用儲存在獨立檔案中的中間介面，可以匯入到兩個依賴檔案中，而不會造成匯入循環。
* 將互相參考的類別移至同一個檔案中，以避免它們之間的任何匯入。
* 如果匯入的宣告僅用於類型，則將匯入陳述式轉換為僅類型匯入（使用 `import type` 語法），因為僅類型匯入不會造成循環。
