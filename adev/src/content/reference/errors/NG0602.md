@name 在反應式內容中呼叫不允許的函數
@category 執行階段
@shortDescription 在反應式內容中呼叫不允許的函數

@description
一個在反應式上下文中不被允許執行的函數從反應式上下文中被呼叫。

例如，無法在 `computed` 或正在執行中的 `effect` 內安排 `effect`。
避免將函式（例如 `effect`）呼叫為範本表達式的一部分，因為這些函式會在它們自己的反應式內容中執行。

計算過的表達式預期是純粹的。
純粹表示表達式不會觸發任何副作用。
副作用是像安排 `afterRender`、建立新的 `effect` 或訂閱 observables 的操作。

為了避免常見的陷阱，一些操作在反應式內容裡明文禁止。
舉例來說，在 `computed` 裡使用 `afterRender` 會在每次計算式表達式評估時，排定新的渲染掛勾。
這很可能不是預期的行為，而且會降低應用程式的效能。

### 修復錯誤

這個錯誤指南並非詳盡無遺。
它擷取了一些常見情境以及如何解決錯誤。

#### `afterRender`

將 `afterRender` 的呼叫移到 reactive context 外面。

在元件的類別建構函數中排程 `after render` 掛鉤是一個不錯的地方。
或者，使用 `untracked` 離開反應式內容並明確選擇不使用此錯誤。

#### `effect`

將 `effect` 的呼叫移至反應式內容外。

安排效果的適當位置是在 `@Component` 的類別建構函數中。

#### `toSignal``

將呼叫 `toSignal` 移到 reactive context 外部。

```typescript
result = computed(() => {
  const dataSignal = toSignal(dataObservable$);
  return doSomething(dataSignal());
});
```

可重構為：

```typescript
dataSignal = toSignal(dataObservable$);
result = computed(() => doSomething(dataSignal()));
```

或者，如果這不可行，請考慮手動訂閱可觀察到的內容。

作為最後的手段，使用 `untracked` 離開 reactivate 環境。
小心，因為離開 reactivate 環境可能會導致在 `untracked` 內忽略信號讀取。

@debugging

錯誤訊息提到意外呼叫的函數。
在您的應用程式碼中尋找此函數呼叫。

或者，瀏覽器中的堆疊追蹤會顯示函數在哪裡被呼叫，以及它的位置。
