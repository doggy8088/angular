# Nullish coalescing 不為 nullable

此診斷偵測 Angular 範本中無用的空值合併運算子 \(`??`\) 字元。
具體來說，它會尋找輸入不為「可為空值」，代表其類型不包含 `null` 或 `undefined` 的運算。
對於此類值，`??` 的右側永遠不會使用。

<docs-code language="typescript">

import {Component} from '@angular/core';

@Component({
  // Template displays `username` if present, falls back to 'root' if it is
  // `null` or `undefined`.
  template: `<div>{{ username ?? 'root' }}</div>`,
})
class MyComponent {
  // `username` is declared as a `string` which *cannot* be `null` or
  // `undefined`.
  username: string = 'Angelino';
}

</docs-code>

## 有什麼問題？

使用非可空輸入的空值合併運算子沒有效果，且表示值允許的類型與範本中呈現的方式之間存在差異。
開發人員可能會合理地假設在某些情況下會顯示空值合併運算符號的右側，但實際上絕不會顯示。
這可能會導致對程式預期輸出的混淆。

## 我該怎麼做？

更新範本和已宣告類型以保持同步。
仔細檢查輸入的類型，並確認是否實際上預期為可為空。

如果輸入應該為可為空，請將 `null` 或 `undefined` 加入其類型以表示這點。

<docs-code language="typescript">

import {Component} from '@angular/core';

@Component({
  template: `<div>{{ username ?? 'root' }}</div>`,
})
class MyComponent {
  // `username` is now nullable. If it is ever set to `null`, 'root' will be
  // displayed.
  username: string | null = 'Angelino';
}

</docs-code>

如果輸入不應為 *nullable*，請刪除 `??` 運算符及其右運算元，因為 TypeScript 保證該值永遠是非 *nullable* 的。

<docs-code language="typescript">

import {Component} from '@angular/core';

@Component({
  // Template always displays `username`, which is guaranteed to never be `null`
  // or `undefined`.
  template: `<div>{{ username }}</div>`,
})
class MyComponent {
  username: string = 'Angelino';
}

</docs-code>

## 組態需求

必須啟用 [`strictTemplates`](tools/cli/template-typecheck#strict-mode) 才能發出任何延伸診斷。
也必須啟用 [`strictNullChecks`](tools/cli/template-typecheck#strict-null-checks) 才能發出 `nullishCoalescingNotNullable` 診斷。

## 如果我無法避免這件事怎麼辦？

這個診斷可以透過編輯專案的 `tsconfig.json` 檔案停用：

<docs-code language="json">
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "nullishCoalescingNotNullable": "suppress"
      }
    }
  }
}
</docs-code>

參閱 [進階診斷設定](extended-diagnostics#configuration) 以取得更多資訊。
