# 可選鏈不是可為空

此診斷偵測到當可選鏈結操作（`.?`）的左側在 Angular 範本中，其類型未包括 `null` 或 `undefined`。

<docs-code language="typescript">

import {Component} from '@angular/core';

@Component({
  // Print the user's name safely, even if `user` is `null` or `undefined`.
  template: `<div>User name: {{ user?.name }}</div>`,
})
class MyComponent {
  // `user` is declared as an object which *cannot* be `null` or `undefined`.
  user: { name: string } = { name: 'Angelino' };
}

</docs-code>

## 有什麼問題？

使用具有非空輸入的選用鏈運算子沒有任何效果，並且表示值允許的類型與它在範本中呈現的方式之間存在差異。
開發人員可能會合理地假設選用鏈運算子的輸出可能是 `null` 或 `undefined`，但實際上它永遠不會是這兩個值中的任何一個。
這可能會導致對程式預期輸出的混淆。

## 我該怎麼做？

更新範本和已宣告類型以保持同步。
仔細檢查輸入的類型，並確認是否實際上預期為可為空。

如果輸入應該為可為空，請將 `null` 或 `undefined` 加入其類型以表示這點。

<docs-code language="typescript">

import {Component} from '@angular/core';

@Component({
  // If `user` is nullish, `name` won't be evaluated and the expression will
  // return the nullish value (`null` or `undefined`).
  template: `<div>{{ user?.name }}</div>`,
})
class MyComponent {
  user: { name: string } | null = { name: 'Angelino' };
}

</docs-code>

如果輸入不應為可為空，請刪除 `?` 營運子。

<docs-code language="typescript">

import {Component} from '@angular/core';

@Component({
  // Template always displays `name` as `user` is guaranteed to never be `null`
  // or `undefined`.
  template: `<div>{{ foo.bar }}</div>`,
})
class MyComponent {
  user: { name: string } = { name: 'Angelino' };
}

</docs-code>

## 組態需求

必須啟用 [`strictTemplates`](tools/cli/template-typecheck#strict-mode) 才能發出任何延伸診斷。
也必須啟用 [`strictNullChecks`](tools/cli/template-typecheck#strict-null-checks) 才能發出 `optionalChainNotNullable` 診斷。

## 如果我無法避免這件事怎麼辦？

這個診斷可以透過編輯專案的 `tsconfig.json` 檔案停用：

<docs-code language="json">
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "optionalChainNotNullable": "suppress"
      }
    }
  }
}
</docs-code>

參閱 [進階診斷設定](extended-diagnostics#configuration) 以取得更多資訊。
