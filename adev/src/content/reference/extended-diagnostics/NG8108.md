# `ngSkipHydration` 應為靜態屬性

`ngSkipHydration` 是一個特殊屬性，用來向 Angular 表示特定元件應該選擇退出 [hydration](guide/hydration)。
這個診斷確保這個屬性 `ngSkipHydration` 是靜態設定的，而且值被設定為 `"true"` 或空值。

<docs-code language="typescript">

import {Component} from '@angular/core';

@Component({
  template: `<user-viewer ngSkipHydration="hasUser" />`,
})
class MyComponent {
  hasUser = true;
}

</docs-code>

## 有什麼問題？

作為 Angular 實施的特殊屬性，`ngSkipHydration` 需要可進行靜態分析，以便 Angular 在編譯時知道是否需要為元件進行水化。

## 我該怎麼做？

當使用 `ngSkipHydration` 時，請確保它被設定為靜態屬性（即您不使用 Angular 範本繫結語法）。

<docs-code language="typescript">

import {Component} from '@angular/core';

@Component({
  template: `
    <user-viewer ngSkipHydration />
    <user-viewer ngSkipHydration="true" />
  `,
})
class MyComponent {}

</docs-code>

如果需要條件式，您可以將該元件包覆在 `*ngIf` 中。

<docs-code language="html">

import {Component} from '@angular/core';

@Component({
  template: `
    <div *ngIf="hasUser; else noUser">
      <user-viewer ngSkipHydration />
    </div>

    <ng-template #noUser>
      <user-viewer />
    </ng-template>

`,
})
class MyComponent {}

</docs-code>

## 組態需求

必須啟用 [`strictTemplates`](tools/cli/template-typecheck#strict-mode) 才能發出任何延伸診斷。
`skipHydrationNotStatic` 除了 `strictTemplates` 之外沒有其他額外需求。

## 如果我無法避免這件事怎麼辦？

這個診斷可以透過編輯專案的 `tsconfig.json` 檔案停用：

<docs-code language="json">
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "skipHydrationNotStatic": "suppress"
      }
    }
  }
}
</docs-code>

參閱 [進階診斷設定](extended-diagnostics#configuration) 以取得更多資訊。
