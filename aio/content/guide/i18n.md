# 國際化（i18n）

應用程式國際化是一個多面向的開發領域，著重於讓應用程式能供全球使用者使用且友善易用。本頁說明 Angular 的國際化（i18n）工具，能幫助你讓應用程式支援多種語言。

請參閱 <live-example downloadOnly name="i18n">i18n 範例</live-example>，這是一個翻譯成法文的 AOT 編譯應用程式的簡單範例。

{@a angular-i18n}

## Angular 與 i18n

*國際化*是設計與準備你的應用程式，使其能以不同語言使用的過程。
*在地化*是將你已國際化的應用程式翻譯成特定語言、供特定地區設定使用的過程。

Angular 簡化了國際化的下列面向：
* 以本地格式顯示日期、數字、百分比與貨幣。
* 準備元件範本中的文字以供翻譯。
* 處理單字的複數形式。
* 處理替代文字。

對於在地化，你可以使用 [**Angular CLI**](https://cli.angular.io/) 產生建立翻譯者檔案所需的大部分樣板，並以多種語言發佈你的應用程式。
在你設定好應用程式使用 i18n 之後，CLI 可以協助你完成下列步驟：
* 將可本地化的文字抽取到一個檔案中，讓你送出進行翻譯。
* 使用翻譯後的文字，為指定的地區設定建置與提供應用程式。
* 建立你的應用程式的多種語言版本。

## 設定你應用程式的地區設定

地區設定是一個識別碼（id），指的是一組在世界某個區域（例如國家）內往往共享的使用者偏好。本文件將地區設定識別碼稱為「地區設定」或「地區設定 id」。

Unicode 地區設定識別碼由 Unicode 語言識別碼，以及（選擇性的）字元 `-` 加上地區設定擴充部分組成。（基於歷史因素，字元 `_` 也受支援，可替代 `-`。） 例如，在地區設定 id `fr-CA` 中，`fr` 指的是法文語言識別碼，而 `CA` 指的是地區設定擴充部分加拿大。

<div class="alert is-critical">

Angular 遵循 Unicode LDML 慣例，使用以 [BCP47](http://www.rfc-editor.org/rfc/bcp/bcp47.txt) 規範為基礎的穩定識別碼（Unicode 地區設定識別碼）。在你定義你的地區設定時，遵循這個慣例非常重要，因為 Angular i18n 工具使用這個地區設定 id 來尋找正確對應的地區設定資料。

</div>

預設情況下，Angular 使用地區設定 `en-US`，即美國所使用的英文。

若要將應用程式的地區設定設為其他值，請使用 CLI 參數 `--configuration`，並傳入你想使用的地區設定 id：

## 範本翻譯

<div class="alert is-helpful">

  本文件將一個可翻譯文字的單位稱為「文字」、「訊息」或「文字訊息」。

</div>

i18n 範本翻譯流程有四個階段：

1. 標記元件範本中的靜態文字訊息以供翻譯。

2. 建立翻譯檔案：使用 Angular CLI 的 `xi18n` 指令，將標記的文字抽取到符合業界標準的翻譯來源檔案中。

3. 編輯產生的翻譯檔案：將抽取的文字翻譯成目標語言。

4. 將完成的翻譯檔案合併進應用程式。為此，請使用 Angular CLI 的 `build` 命令編譯應用程式，選擇一個[地區設定專屬的設定](#merge-aot)，或指定下列命令選項。

    * `--i18nFile`=*翻譯檔案的路徑*
    * `--i18nFormat`=*翻譯檔案的格式*
    * `--i18nLocale`= *地區設定 id*

該命令會以翻譯後的文字取代原始訊息，並以目標語言產生應用程式的新版本。

你需要為每種支援的語言，分別建置並部署應用程式的一個獨立版本。

#### 定義唯一的自訂 id

請務必定義唯一的自訂 id。如果你對兩則不同的文字訊息使用相同的 id，只有第一則會被抽取，而且它的翻譯會用來取代兩則原始文字訊息。

在下方的範例中，自訂 id `myId` 被用於兩則不同的訊息：

  ```html
    <h3 i18n="@@myId">Hello</h3>
    <!-- ... -->
    <p i18n="@@myId">Good bye</p>
  ```

考慮這個法文翻譯：

  ```xml
    <trans-unit id="myId" datatype="html">
      <source>Hello</source>
      <target state="new">Bonjour</target>
    </trans-unit>
  ```

因為自訂 id 相同，最終翻譯中的兩個元素都包含相同的文字 `Bonjour`：

  ```html
    <h3>Bonjour</h3>
    <!-- ... -->
    <p>Bonjour</p>
  ```

## 複數與選擇的正規表示式

不同的語言有不同的複數規則與文法結構，增加了翻譯工作的複雜度。
你可以將正規表示式與 `plural` 和 `select` 子句搭配使用，提供有助於這些情況翻譯的模式。

{@a plural-ICU}

### 複數化

假設你想表示某件事是「x 分鐘前更新的」。
在英文中，依據分鐘數，你可以顯示 "just now"、"one minute ago"，
或 "x minutes ago"（其中 x 是實際數字）。
其他語言可能以不同的方式表達基數。

<code-example path="i18n/src/app/app.component.html" region="i18n-plural" title="src/app/app.component.html" linenums="false">
</code-example>

* 第一個參數是 key。它繫結到元件屬性（`minutes`），該屬性決定
分鐘數。
* 第二個參數將其標識為 `plural` 翻譯類型。
* 第三個參數定義一個複數化模式，由複數化類別與其對應值組成。

<div class="alert is-helpful">

  這個語法符合
  <a href="http://cldr.unicode.org/index/cldr-spec/plural-rules" title="Pluralization Rules">CLDR 複數化規則</a>所規範的
  <a href="http://userguide.icu-project.org/formatparse/messages" title="ICU Message Format">ICU Message Format</a>。

</div>

複數化類別包括（視語言而定）：

* =0 (or any other number)
* zero
* one
* two
* few
* many
* other

在複數化類別之後，將預設的英文文字放在大括號（`{}`）中。

在上方的範例中，三個選項是依據該複數化模式指定的。談到
零分鐘時，你使用 `=0 {just now}`。一分鐘時，你使用 `=1 {one minute}`。
任何未匹配的基數使用 `other {{{minutes}} minutes ago}`。如果複數化規則不同，你可以選擇為二、三或任何其他數字加入模式。對於
"minute" 這個範例，在英文中只需要這三個模式。

<div class="alert is-helpful">

## 建立翻譯來源檔案

當你的應用程式就緒時，你可以使用 Angular CLI 將以 `i18n` 標記的文字訊息與以 `i18n-x` 標記的屬性抽取到翻譯來源檔案中。
在應用程式專案的根目錄開啟終端機視窗，執行 CLI 指令 `xi18n`。

<code-example language="sh" class="code-shell">
  ng xi18n
</code-example>

預設情況下，該指令會在你的 `src/` 資料夾中建立一個名為 `messages.xlf` 的檔案。

<div class="alert is-helpful">

如果你不使用 CLI，你有兩個選擇：
* 你可以直接使用 `@angular/compiler-cli` 套件中的 `ng-xi18n` 工具。
更多資訊，請參閱 [CLI 文件中的 i18n](https://github.com/angular/angular-cli/wiki/xi18n)。
* 你可以使用 `@ngtools/webpack` 套件中的 CLI Webpack 外掛 `AngularCompilerPlugin`。
設定參數 `i18nOutFile` 與 `i18nOutFormat` 即可觸發抽取。
更多資訊，請參閱 [Angular Ahead-of-Time Webpack 外掛文件](https://github.com/angular/angular-cli/tree/master/packages/%40ngtools/webpack)。

### 輸出選項

你可以提供指令選項來變更抽取檔案的格式、名稱、位置與來源地區設定。
例如，若要在 `src/locale` 資料夾中建立檔案，請指定輸出路徑：

<code-example language="sh" class="code-shell">
  ng xi18n --output-path src/locale
</code-example>

預設情況下，`xi18n` 指令會產生一個名為 `messages.xlf` 的翻譯檔案，格式為
<a href="https://en.wikipedia.org/wiki/XLIFF">XML Localization Interchange File Format
(XLIFF, version 1.2)</a>。

該指令可以讀寫三種翻譯格式的檔案：
* XLIFF 1.2 (default)
* XLIFF 2
* <a href="http://cldr.unicode.org/development/development-process/design-proposals/xmb" >XML Message
Bundle (XMB)</a>

你可以使用 `--i18nFormat` 命令選項明確指定翻譯格式，如這些範例命令所示：

<code-example language="sh" class="code-shell">
ng xi18n  --i18n-format=xlf
ng xi18n  --i18n-format=xlf2
ng xi18n  --i18n-format=xmb
</code-example>

本指南中的範例使用預設的 XLIFF 1.2 格式。

<div class="alert is-helpful">

  XLIFF 檔案的副檔名是 .xlf。XMB 格式產生 .xmb 來源檔案，但使用
  .xtb（XML Translation Bundle：XTB）翻譯檔案。

</div>

你可以使用 `--outFile` 指令選項變更抽取工具所產生的翻譯來源檔案名稱：

<code-example language="sh" class="code-shell">

  ng xi18n --out-file source.xlf

</code-example>

你可以使用 `--i18n-locale` 指令選項指定應用程式的基礎地區設定：

<code-example language="sh" class="code-shell">

  ng xi18n --i18n-locale fr

</code-example>

抽取工具使用地區設定將應用程式地區設定資訊加入你的翻譯來源檔案。這個資訊不會被 Angular 使用，但外部翻譯工具可能需要它。

{@a translate}

## 翻譯來源文字

`ng xi18n` 命令會在專案的 `src` 資料夾中產生一個名為 `messages.xlf` 的翻譯來源檔案。
下一步是將此來源檔案中的顯示字串翻譯成語言專屬的翻譯檔案。本指南中的範例將建立一個法文翻譯檔案。

{@a localization-folder}

### 建立在地化資料夾

大多數應用程式會被翻譯成多種其他語言。因此，標準做法是讓專案結構反映整個國際化工作。

<div class="alert is-helpful">

  在地化與國際化是
  <a href="https://en.wikipedia.org/wiki/Internationalization_and_localization">不同但
  密切相關的術語</a>。

</div>

一種做法是專門用一個資料夾來放本地化內容，並將相關資產（例如國際化檔案）儲存在其中。

本指南遵循這種做法。它在 `src/` 之下有一個 `locale` 資料夾。
該資料夾中的資產，其副檔名與其關聯的地區設定相符。

### 建立翻譯檔案

對於每個翻譯來源檔案，必須至少有一個語言翻譯檔案來承載翻譯結果。

以這個範例而言：

1. 複製一份 `messages.xlf` 檔案。
2. 將複本放入 `locale` 資料夾。
3. 將複本重新命名為 `messages.fr.xlf`，作為法文翻譯。

如果你要翻譯成其他語言，你會為每種目標語言重複這些步驟。

## 將完成的翻譯檔案合併到應用程式

若要將翻譯後的文字合併進元件範本，請使用完成的翻譯檔案來編譯應用程式。

 提供 Angular 編譯器三項翻譯專屬的資訊：

  * 翻譯檔案。
  * 翻譯檔案的格式。
  * 地區設定（例如 `fr` 或 `en-US`）。

無論翻譯檔案是 `.xlf` 格式，還是 Angular 能理解的其他格式（例如 `.xtb`），編譯流程都相同。

你提供這些資訊的方式，取決於你是用 JIT 編譯器還是 AOT 編譯器進行編譯。

  * 使用 [AOT](guide/i18n#merge-aot) 時，你以組態設定的形式提供這些資訊。
  * 使用 [JIT](guide/i18n#merge-jit) 時，你在啟動時提供這些資訊。

{@a merge-aot}

### 與 AOT 編譯器合併

[AOT 編譯器](guide/glossary#aot)是建置流程的一部分，會產生小巧、快速、可直接執行的應用程式套件，通常用於生產環境。

當你使用 AOT 編譯器進行國際化時，你必須為每種語言預先建置一個獨立的應用程式套件，並根據伺服器端的語言偵測或 URL 參數，提供適當的套件。

若要指示 AOT 編譯器使用你的翻譯設定，請在你的 `angular.json` 檔案中設定三個「i18n」建置設定選項。

* `i18nFile`：翻譯檔案的路徑。
* `i18nFormat`：翻譯檔案的格式。
* `i18nLocale`：地區設定 id。

你也應該透過設定 `outputPath` 設定選項，將輸出導向地區設定專屬的資料夾，讓它與應用程式的其他地區設定版本分開存放。

```
"build": {
  ...
  "configurations": {
    ...
    "fr": {
      "aot": true,
      "outputPath": "dist/my-project-fr/",
      "i18nFile": "src/locale/messages.fr.xlf",
      "i18nFormat": "xlf",
      "i18nLocale": "fr",
      ...
    }
  }
},
"serve": {
  ...
  "configurations": {
    ...
    "fr": {
      "browserTarget": "*project-name*:build:fr"
    }
  }
}
```

接著你可以將這個設定傳給 `ng serve` 或 `ng build` 指令。
下方的範例展示如何提供本指南前面章節所建立的法文語言檔案：

<code-example language="sh" class="code-shell">
  ng serve --configuration=fr
</code-example>

對於生產建置，你要在 CLI 設定檔 `angular.json` 中定義一個獨立的 `production-fr` 建置設定。

```
...
"architect": {
  "build": {
    "builder": "@angular-devkit/build-angular:browser",
    "options": { ... },
    "configurations": {
      "fr": {
        "aot": true,
        "outputPath": "dist/my-project-fr/",
        "i18nFile": "src/locale/messages.fr.xlf",
        "i18nFormat": "xlf",
        "i18nLocale": "fr",
        "i18nMissingTranslation": "error",
      }
// ...
"serve": {
  "builder": "@angular-devkit/build-angular:dev-server",
  "options": {
    "browserTarget": "my-project:build"
  },
  "configurations": {
    "production": {
      "browserTarget": "my-project:build:production"
    },
    "fr": {
      "browserTarget": "my-project:build:fr"
    }
  }
},

```

相同的設定選項也可以透過 CLI，搭配你現有的 `production` 設定一起提供。

<code-example language="sh" class="code-shell">
  ng build --prod --i18n-file src/locale/messages.fr.xlf --i18n-format xlf --i18n-locale fr
</code-example>

### 與 JIT 編譯器合併

[JIT 編譯器](guide/glossary#jit)會在應用程式載入時，在瀏覽器中編譯你的應用程式。
若要支援使用 JIT 編譯器進行翻譯，你必須完成下列事項：

1. 將適當的語言翻譯檔案以字串常數的形式匯入。
2. 為 JIT 編譯器建立對應的翻譯提供者。
3. 使用這些提供者啟動應用程式。

有三個提供者會告訴 JIT 編譯器，在編譯應用程式時如何翻譯特定語言的範本文字：

* `TRANSLATIONS` 是包含翻譯檔案內容的字串。
* `TRANSLATIONS_FORMAT` 是檔案的格式：`xlf`、`xlf2` 或 `xtb`。
* `LOCALE_ID` 是目標語言的地區設定。

### 回報缺失的翻譯

預設情況下，當翻譯缺失時，建置會成功，但會產生例如
`Missing translation for message "foo"` 的警告。你可以設定 Angular 編譯器所產生警告的等級：

* Error：擲出錯誤。如果你使用 AOT 編譯，建置會失敗。如果你使用 JIT
編譯，應用程式將無法載入。
* Warning（預設）：在主控台或 shell 中顯示 'Missing translation' 警告。
* Ignore：不做任何事。

你在 Angular CLI 建置設定的 `configurations` 區段中指定警告等級。下方的範例示範如何將警告等級設為 error：

```
"configurations": {
  ...
  "fr": {
    ...
    "i18nMissingTranslation": "error"
  }
}
```

如果你使用 JIT 編譯器，請在啟動時的編譯器設定中加入 'MissingTranslationStrategy' 屬性，來指定警告等級。下方的範例示範如何將警告等級設為 error：

### 為多個地區設定建置

當你使用 CLI 的 `build` 或 `serve` 命令為不同地區設定建置應用程式時，請使用 `--outputPath` 命令選項（連同 i18n 專屬的命令選項）來變更輸出路徑，讓翻譯檔案儲存到不同的位置。
當你從子目錄提供地區設定專屬的版本時，你也可以指定 `--baseHref` 選項，來變更應用程式使用的基底 URL。

例如，如果你的應用程式法文版是從 https://myapp.com/fr/ 提供的，法文版的建置設定如下。

```
"configurations": {
  "fr": {
    "aot": true,
    "outputPath": "dist/my-project-fr/",
    "baseHref": "/fr/",
    "i18nFile": "src/locale/messages.fr.xlf",
    "i18nFormat": "xlf",
    "i18nLocale": "fr",
    "i18nMissingTranslation": "error",
  }
```

如需更多關於如何建立指令碼以多種語言產生應用程式，以及如何設定 Apache 2 從不同子目錄提供它們的細節，請閱讀 [Philippe Martin 的這篇教學](https://medium.com/@feloy/deploying-an-i18n-angular-app-with-angular-cli-fc788f17e358#.1xq4iy6fp)。
