# 將你的應用程式在地化

{@searchKeywords i18n}
{@a angular-i18n}

*國際化*（i18n）是設計並準備你的應用程式，讓它能在世界各地的不同地區設定中使用的程序。
*在地化*是為不同地區設定建立應用程式版本的程序，其中包括將文字抽取出來翻譯成不同語言，以及依據特定地區設定格式化資料。

*地區設定*識別人們使用某種語言或其變體所在的區域（例如國家）。地區設定決定了日期、時間、數字與貨幣的格式化與解析方式，以及度量單位，還有時區、語言與國家等翻譯後的名稱。

<div class="alert is-helpful">

為所有目標地區設定建立一個可適應的使用者介面，並考量不同語言在間距上的差異。若要了解詳情，請見[如何著手國際化](https://marketfinder.thinkwithgoogle.com/intl/en_us/guide/how-to-approach-i18n/#overview "如何著手國際化")。

</div>

使用 Angular 將你的應用程式國際化：

* 使用內建管道，以當地格式顯示日期、數字、百分比與貨幣。
* 在元件範本中標記文字以供翻譯。
* 標記運算式的複數形式以供翻譯。
* 標記替代文字以供翻譯。

為你的應用程式做好面對國際受眾的準備後，使用 [Angular CLI](cli) 執行下列工作，將應用程式在地化：

* 使用 CLI 將標記的文字擷取到*來源語言*檔案。
* 為每種語言複製一份此檔案，並將這些*翻譯檔案*傳送給譯者或服務。
* 在為一個或多個地區設定建置你的應用程式時，使用 CLI 合併已完成的翻譯檔案。

  若要探索本指南使用的附法文翻譯的範例應用程式，請見 <live-example></live-example>。

</div>

## 依 ID 參照地區設定

使用 Unicode *地區設定識別碼*（ID）來參照地區設定；它指定了語言、國家，以及用於進一步變體或細分的選用代碼。

<div class="callout is-helpful">
<header>Unicode 地區設定識別碼</header>

* 語言代碼清單請見 [ISO 639-2](https://www.loc.gov/standards/iso639-2/ "ISO 639-2 註冊管理機構")。
* 這些 ID 符合 Unicode Common Locale Data Repository（CLDR）。
若要進一步了解 Unicode 地區設定識別碼，請見 [CLDR 核心規範](http://cldr.unicode.org/core-spec#Unicode_Language_and_Locale_Identifiers "CLDR - Unicode Common Locale Data Repository")。
* CLDR 與 Angular 的識別碼都以 [BCP47 標籤](http://www.rfc-editor.org/rfc/bcp/bcp47.txt "用於識別語言的 BCP47 標籤") 為基礎。

</div>

此 ID 由語言識別碼（例如英文的 `en` 或法文的 `fr`）、一個連字號（`-`），以及地區設定擴充部分（例如美國的 `US` 或加拿大的 `CA`）組成。
例如，`en-US` 指美國的英文，`fr-CA` 指加拿大的法文。
Angular 使用此 ID 來尋找正確對應的地區設定資料。

<div class="alert is-helpful">

許多國家（例如法國與加拿大）使用相同的語言（法文，識別碼為 `fr`），但在文法、標點符號，以及貨幣、十進位數字與日期的格式上有所不同。
在地化你的應用程式時，請使用更具體的地區設定 ID，例如加拿大的法文（`fr-CA`）。

</div>

Angular 預設使用 `en-US`（美國英文）作為你應用程式的來源地區設定。

[Angular 儲存庫](https://github.com/angular/angular/tree/master/packages/common/locales "Angular 儲存庫中的常見地區設定")包含常見的地區設定。
你可以在應用程式的[工作區設定](guide/workspace-config "Angular 工作區設定")檔案（`angular.json`）的 `sourceLocale` 欄位中設定來源地區設定，藉此變更建置時應用程式的來源地區設定。
建置程序（見本指南的[將翻譯合併至應用程式](#merge)）會使用你應用程式的 `angular.json` 檔案，自動設定 [`LOCALE_ID`](api/core/LOCALE_ID "LOCALE_ID 的 API 參考") 權杖並載入地區設定資料。

{@a i18n-pipes}

## 依地區設定格式化資料

Angular 提供下列內建的資料轉換[管道](guide/glossary#pipe "管道的定義")，它們使用 [`LOCALE_ID`](api/core/LOCALE_ID "LOCALE_ID 的 API 參考") 權杖，依地區設定的規則格式化資料：

* [`DatePipe`](api/common/DatePipe)：格式化日期值。
* [`CurrencyPipe`](api/common/CurrencyPipe)：將數字轉換為貨幣字串。
* [`DecimalPipe`](/api/common/DecimalPipe)：將數字轉換為十進位數字字串。
* [`PercentPipe`](api/common/PercentPipe)：將數字轉換為百分比字串。

例如，`{{today | date}}` 使用 `DatePipe`，以 `LOCALE_ID` 中地區設定的格式顯示目前日期。

若要覆寫 `LOCALE_ID` 的值，請加入 `locale` 參數。
例如，若要強制貨幣使用 `en-US`，無論你為 `LOCALE_ID` 設定哪個語言地區設定，都可以使用這個形式：`{{amount | currency : 'en-US'}}`。

<div class="callout is-helpful">
<header>說明如何控制文字擷取與合併</header>

Angular 擷取工具（見本指南的[使用翻譯檔案](#ng-xi18n)）會為範本中的每個 `i18n` 屬性產生一個翻譯單元條目。
它會根據*意義*與*說明*，為每個翻譯單元指派一個唯一的 ID。

具有不同*意義*的相同文字元素，會以不同的 ID 擷取。
例如，「right」這個字在一處以 `correct` 為意義（如「You are right」），在另一處以 `direction` 為意義（如「Turn right」），這個字就會被翻譯成不同的譯文，並以不同的翻譯條目合併回應用程式。

如果相同的文字元素有不同的*說明*、但有相同的*意義*，它們只會被擷取一次，且只有一個 ID。那一個翻譯條目會在相同文字元素出現的任何位置合併回應用程式。

</div>

### 標記複數與替代文字以供翻譯

不同語言有不同的複數化規則與文法結構，可能讓翻譯變得困難。
若要簡化翻譯，請將 International Components for Unicode（ICU）子句與正規運算式搭配使用，例如以 `plural` 標記複數數量的用法、以 `select` 標記替代文字的選項。

<div class="alert is-helpful">

ICU 子句遵循 [CLDR 複數化規則](http://cldr.unicode.org/index/cldr-spec/plural-rules "複數化規則") 中指定的 [ICU 訊息格式](http://userguide.icu-project.org/formatparse/messages "ICU 訊息格式")。

</div>

{@a plural-ICU}

#### 標記複數

使用 `plural` 子句，標記逐字翻譯可能失去意義的運算式。

例如，若你想以英文顯示「updated x minutes ago」，你可能會想顯示「just now」、「one minute ago」或「_x_ minutes ago」（其中 _x_ 是實際數字）。
其他語言可能以不同的方式表達這種基數。
下列範例顯示如何使用 `plural` 子句表達這三種情況：

<code-example path="i18n/src/app/app.component.html" region="i18n-plural" header="src/app/app.component.html"></code-example>

在上例中：

* 第一個參數 `minutes` 繫結至元件屬性（`minutes`），它決定分鐘數。

* 第二個參數指明這是 `plural` 翻譯型別。

* 第三個參數定義複數化類別及其對應值的樣式：
  * 分鐘數為零時，使用 `=0 {just now}`。
  * 分鐘數為一分鐘時，使用 `=1 {one minute}`。
  * 對任何未相符的基數，使用 `other {{{minutes}} minutes ago}`。
  你可以搭配 `plural` 子句，在運算式中使用 HTML 標記與[插值](guide/glossary#interpolation "插值的定義")，例如 `{{{minutes}}`。
  * 在複數化類別之後，將預設文字（英文）放在大括號（`{}`）內。

複數化類別包括（視語言而定）：

* `=0`（或任何其他數字）
* `zero`
* `one`
* `two`
* `few`
* `many`
* `other`

<div class="callout is-important">
<header>部分地區設定可能不支援某些複數化類別</header>

許多地區設定不支援某些複數化類別。
例如，預設地區設定（`en-US`）與其他地區設定（例如 `es`）的 `plural()` 函式非常簡單，不支援 `few` 類別。
下列顯示 [en-US](https://github.com/angular/angular/blob/ecffc3557fe1bff9718c01277498e877ca44588d/packages/core/src/i18n/locale_en.ts#L15-L18) 的 `plural()` 函式：

```
function plural(n: number): number {
  let i = Math.floor(Math.abs(n)), v = n.toString().replace(/^[^.]*\.?/, '').length;
  if (i === 1 && v === 0) return 1;
  return 5;
}
```

此函式只會回傳 1（`one`）或 5（`other`）。
`few` 類別永遠不會相符。
如果沒有任何複數化類別相符，Angular 會嘗試相符 `other`。
請使用 `other` 作為類別缺失時的標準備援。

若要進一步了解複數化類別，請見 CLDR - Unicode Common Locale Data Repository 中的[選擇複數類別名稱](http://cldr.unicode.org/index/cldr-spec/plural-rules#TOC-Choosing-Plural-Category-Names)。

</div>

### 擷取來源語言檔案

若要擷取來源語言檔案，請開啟終端機視窗、切換到你的應用程式專案的根目錄，然後執行下列 CLI 指令：

<code-example language="sh" class="code-shell">
  ng xi18n
</code-example>

`xi18n` 指令會使用 [XML Localization Interchange File Format（XLIFF，version 1.2）](https://en.wikipedia.org/wiki/XLIFF "關於 XLIFF 的 Wikipedia 頁面")，在你專案的根目錄中建立一個名為 `messages.xlf` 的來源語言檔案。

使用下列 `xi18n` 指令選項，可以變更來源語言檔案的位置、格式與檔案名稱：

* `--output-path`：變更位置。
* `--format`：變更格式。
* `--outFile`：變更檔案名稱。

注意：`--i18n-locale` 選項已棄用。
Angular 9 使用在你應用程式的[工作區設定](guide/workspace-config "Angular 工作區設定")檔案（`angular.json`）中設定的來源地區設定。

<div class="alert is-helpful">

ng xi18n 的擷取機制使用 ViewEngine 編譯器，它無法處理 Ivy 編譯器能處理的部分程式碼語法。這個問題的修復目前正在開發中。若要追蹤或參與這個修復，請見 [PR 32912](https://github.com/angular/angular/pull/32912)。

</div>

#### 變更來源語言檔案的位置

若要在 `src/locale` 目錄中建立檔案，請將輸出路徑指定為選項，如下列範例所示：

<code-example language="sh" class="code-shell">
  ng xi18n --output-path src/locale
</code-example>

{@a other-formats}

#### 變更來源語言檔案的格式

`xi18n` 指令可以讀寫三種翻譯格式的檔案：

* XLIFF 1.2（預設）
* XLIFF 2
* [XML Message Bundle (XMB)](http://cldr.unicode.org/development/development-process/design-proposals/xmb)

使用 `--format` 指令選項明確指定翻譯格式，如下列範例所示：

<code-example language="sh" class="code-shell">
ng xi18n  --format=xlf
ng xi18n  --format=xlf2
ng xi18n  --format=xmb
</code-example>

<div class="alert is-helpful">

  XLIFF 檔案使用副檔名 `.xlf`。
  XMB 格式會產生 `.xmb` 來源語言檔案，但使用 `.xtb`（XML Translation Bundle：XTB）翻譯檔案。

</div>

#### 變更來源語言檔案的名稱

若要變更擷取工具產生的來源語言檔案名稱，請使用 `--outFile` 指令選項：

<code-example language="sh" class="code-shell">
  ng xi18n --out-file source.xlf
</code-example>

{@a localization-folder}

### 為每種語言建立一個翻譯檔案

`ng xi18n` 指令（不帶選項）會在專案的 `src` 資料夾中產生一個名為 `messages.xlf` 的來源語言檔案。
複製來源語言檔案，即可為每種語言建立*翻譯*檔案。
為了避免多份翻譯造成混淆，你應該將各語言的翻譯檔案依地區設定整理在 `src/` 下專用的 `locale` 資料夾中。
請使用與對應地區設定相符的檔案名稱，例如 `messages.fr.xlf`。

例如，若要建立法文翻譯檔案，請依照下列步驟進行：

1. 複製一份 `messages.xlf` 來源語言檔案。
2. 將複本放在 `src/locale` 資料夾中。
3. 將複本重新命名為 `messages.fr.xlf`，作為法文（`fr`）翻譯。
將此翻譯檔案送交譯者。

對你想加入應用程式的每種語言，重複上述步驟。

{@a translate-text-nodes}

## 將翻譯合併至應用程式

若要將完成的翻譯合併至應用程式，請使用 [Angular CLI](guide/glossary#命令列介面command-line-interfacecli "CLI 的定義")，為每個地區設定建置一份應用程式可散發檔案的副本。
建置程序會以翻譯後的文字取代原始文字，並為應用程式的每一份可散發副本設定 `LOCALE_ID` 權杖。
它也會載入並註冊地區設定資料。

合併之後，你可以使用伺服器端語言偵測或不同的子目錄，提供應用程式的每一份可散發副本，如下一節[部署多個地區設定](#deploy-locales)所述。

建置程序使用[預先編譯（AOT）](guide/glossary#預先編譯ahead-of-time-compilationaot)，產生精簡、快速、可直接執行的應用程式。在 Angular 9 中，Ivy 讓開發與生產環境建置預設都使用 AOT，而在地化元件範本也需要 AOT。

<div class="alert is-helpful">

若要了解建置程序的詳細說明，請見[建置與提供 Angular 應用程式](guide/build "建置與提供 Angular 應用程式")。
此建置程序適用於 `.xlf` 格式的翻譯檔案，或 Angular 能理解的其他格式，例如 `.xtb`。

</div>

<div class="alert is-important">

Ivy 不支援在使用 JIT 模式時合併 i18n 翻譯。
如果你[停用 Ivy](guide/ivy#在第-9-版中退出-ivy)並使用 JIT 模式，請見[使用 JIT 編譯器合併](https://v8.angular.tw/guide/i18n#merge-with-the-jit-compiler "使用 JIT 編譯器合併")。

</div>

若要為每個地區設定建置一份獨立的應用程式可散發副本，請在你專案的工作區設定檔 [`angular.json`](guide/workspace-config "Angular 工作區設定") 中[在建置設定中定義地區設定](#localize-config)。
這種方法省去了為每個地區設定執行完整應用程式建置的需要，縮短了建置程序。

接著，你可以使用 `angular.json` 中的 `"localize"` 選項[為每個地區設定產生應用程式版本](#localize-generate)。你也可以使用 Angular CLI 的 [`build`](/cli/build "ng build 的 CLI 參考") 指令搭配 `--localize` 選項，[從命令列建置](#localize-build-command)。

<div class="alert is-helpful">

你也可以選擇[只為單一地區設定套用特定建置選項](#localize-build-one-locale)，建立自訂的地區設定組態。

</div>

{@a localize-config}

### 在建置設定中定義地區設定

使用應用程式建置設定檔（[`angular.json`](guide/workspace-config "Angular 工作區設定")）中的 `i18n` 專案選項，為專案定義地區設定。
下列子選項識別來源語言，並告訴編譯器去哪裡尋找專案支援的翻譯：

* `sourceLocale`：你在應用程式原始碼中使用的地區設定（預設為 `en-US`）
* `locales`：地區設定識別碼對應翻譯檔案的對照表

例如，下列 `angular.json` 檔案摘錄將來源地區設定設為 `en-US`，並提供法文（`fr`）地區設定翻譯檔案的路徑：

<code-example language="json" header="angular.json">
...
"projects": {
  "angular.io-example": {
    ...
    "i18n": {
      "sourceLocale": "en-US",
      "locales": {
        "fr": "src/locale/messages.fr.xlf"
      }
    },
    "architect": {
    ...
    }
}
</code-example>

{@a localize-generate}

### 為每個地區設定產生應用程式變體

若要在建置設定中使用你的地區設定定義，請使用 `angular.json` 中的 `"localize"` 選項，告訴 CLI 要為建置設定產生哪些地區設定：

* 將 `"localize"` 設為 `true`，建置先前在建置設定中定義的所有地區設定。
* 將 `"localize"` 設為先前定義的地區設定識別碼子集陣列，只建置那些地區設定版本。
* 將 `"localize"` 設為 `false`，停用在地化，不產生任何地區設定專屬版本。

<div class="alert is-helpful">

注意：元件範本的在地化需要[預先編譯（AOT）](guide/glossary#預先編譯ahead-of-time-compilationaot)。
若你變更了這項設定，請將 `"aot"` 設為 `true` 以使用 AOT。

</div>

下列範例顯示在 `angular.json` 中將 `"localize"` 選項設為 `true`，如此建置設定中定義的所有地區設定都會被建置：

<code-example language="json" header="angular.json">
"build": {
  "builder": "@angular-devkit/build-angular:browser",
  "options": {
    "localize": true,
    "aot": true,
    ...
</code-example>

<div class="alert is-helpful">

由於 i18n 部署較為複雜，且需要盡量縮短重新建置的時間，開發伺服器一次只支援在地化單一地區設定。
將 `"localize"` 選項設為 `true`，若定義了多個地區設定，使用 `ng serve` 時將會發生錯誤。
將選項設為特定地區設定，例如 `"localize": ["fr"]`，若你想針對特定地區設定（例如 `fr`）進行開發，即可正常運作。

</div>

CLI 會載入並註冊地區設定資料，將每個產生的版本放在地區設定專屬目錄中，與其他地區設定版本分開，並將這些目錄放在專案設定好的 `outputPath` 內。
對每個應用程式變體，`html` 元素的 `lang` 屬性會設為該地區設定。
CLI 也會將地區設定加入設定好的 `baseHref`，調整應用程式每個版本的 HTML 基底 HREF。

你可以將 `"localize"` 屬性設為共用設定，讓所有設定都繼承它（或覆寫它）。

{@a localize-build-command}

### 從命令列建置

你也可以搭配你現有的 `production` 設定，使用 [`ng build`](/cli/build "ng build 的 CLI 參考") 指令的 `--localize` 選項。
CLI 會建置建置設定中定義的所有地區設定，效果類似前一節所述將 `"localize"` 選項設為 `true`。

<code-example language="sh" class="code-shell">
  ng build --prod --localize
</code-example>

{@a localize-build-one-locale}

### 只為單一地區設定套用特定建置選項

若要只對單一地區設定套用特定建置選項，你可以指定單一地區設定，建立自訂的地區設定專屬設定，如下列範例所示：

<code-example language="json" header="angular.json">
"build": {
  ...
  "configurations": {
    ...
    "fr": {
      "localize": ["fr"],
      "main": "src/main.fr.ts",
      ...
    }
  }
},
"serve": {
  ...
  "configurations": {
    ...
    "fr": {
      "browserTarget": "*project-name*:build:fr"
    }
  }
}
</code-example>

接著你可以將這個設定傳給 `ng serve` 或 `ng build` 指令。
下列顯示如何提供本指南範例所建立的法文語言檔案：

<code-example language="sh" class="code-shell">
  ng serve --configuration=fr
</code-example>

<div class="alert is-important">

你可以使用 CLI 開發伺服器（`ng serve`），但只能搭配單一地區設定。

</div>

在生產環境建置中，你可以使用設定組合，同時執行兩個設定：

<code-example language="sh" class="code-shell">
  ng build --configuration=production,fr
</code-example>

<code-example language="json" header="angular.json">
...
"architect": {
  "build": {
    "builder": "@angular-devkit/build-angular:browser",
    "options": { ... },
    "configurations": {
      "fr": {
        "localize": ["fr"],
      }
    }
  },
  ...
  "serve": {
    "builder": "@angular-devkit/build-angular:dev-server",
    "options": {
      "browserTarget": "my-project:build"
    },
    "configurations": {
      "production": {
        "browserTarget": "my-project:build:production"
      },
      "fr": {
        "browserTarget": "my-project:build:fr"
      }
    }
  }
}
</code-example>

{@a missing-translation}

### 回報缺少的翻譯

當翻譯缺少時，建置仍會成功，但會產生類似 `Missing translation for message "foo"` 的警告。你可以設定 Angular 編譯器產生的警告等級：

* `error`：拋出錯誤。若你使用 AOT 編譯，建置將會失敗。
若你使用 JIT 編譯，應用程式將無法載入。
* `warning`（預設）：在主控台或殼層中顯示 `Missing translation` 警告。
* `ignore`：不做任何處理。

請在 Angular CLI 設定檔（`angular.json`）中 `build` 目標的 `options` 區段指定警告等級。下列範例顯示如何將警告等級設為 `error`：

<code-example language="json" header="angular.json">
"options": {
  ...
  "i18nMissingTranslation": "error"
}
</code-example>

## 部署多個地區設定

若 `myapp` 是包含你應用程式可散發檔案的目錄，你通常會將不同版本放在各自的地區設定目錄中，供不同地區設定使用，例如法文版位於 `myapp/fr`、西班牙文版位於 `myapp.com/es`。

帶有 `href` 屬性的 HTML `base` 標籤，指定了相對連結的基底 URI（即 URL）。若你將 `angular.json` 中的 `"localize"` 選項設為 `true` 或地區設定 ID 的陣列，CLI 會將地區設定加入設定好的 `"baseHref"`，調整應用程式每個版本的基底 `href`。你可以在工作區設定檔（`angular.json`）中為每個地區設定指定 `"baseHref"`，如下列範例所示，該範例將 `"baseHref"` 設為空字串：

<code-example language="json" header="angular.json">
...
"projects": {
  "angular.io-example": {
    ...
    "i18n": {
      "sourceLocale": "en-US",
      "locales": {
        "fr": {
          "translation": "src/locale/messages.fr.xlf",
          "baseHref": "" 
        }
      }
    },
    "architect": {
    ...
    }
}
</code-example>

你也可以搭配 [`ng build`](cli/build "ng build 的 CLI 參考") 使用 CLI 的 `--baseHref` 選項，在編譯時期宣告基底 `href`。

為託管多個地區設定而設定伺服器，不在本指南的範圍之內。關於如何將應用程式部署到遠端伺服器的詳細資訊，請見[部署](guide/deployment "Deployment guide")。

### 匯入地區設定資料的全域變體

[Angular 儲存庫](https://github.com/angular/angular/tree/master/packages/common/locales "Angular 儲存庫中的常見地區設定")中的檔案（`@angular/common/locales`）包含你所需的大部分地區設定資料，但某些進階格式化選項需要額外的地區設定資料。

### 以自訂 ID 管理標記的文字

Angular 擷取工具會為範本中的每個 `i18n` 屬性產生一個含有翻譯單元條目的檔案。
如先前（在[說明如何控制文字擷取與合併](#transaction-unit-ids)中）所述，Angular 會為每個翻譯單元指派一個唯一的 ID，如下所示：

<code-example path="i18n/doc-files/messages.fr.xlf.html" header="messages.fr.xlf.html" region="generated-id"></code-example>

當你變更可翻譯的文字時，擷取工具會為該翻譯單元產生新的 ID。
在大多數情況下，文字變更也會需要跟著變更翻譯。
因此，使用新的 ID 能讓文字變更與翻譯保持同步。

不過，有些翻譯系統要求 ID 採用特定的形式或語法。
為了滿足這項要求，你可以用自訂 ID 來標記文字。
雖然大多數開發者不需要使用自訂 ID，但有些人可能想使用具有獨特語法的 ID，來傳達額外的中繼資料（例如文字出現的函式庫、元件，或應用程式中的區域）。

在 `i18n` 屬性中使用 `@@` 前綴，即可指定自訂 ID。
下列範例定義了 `introductionHeader` 自訂 ID：

#### 定義唯一的自訂 ID

請務必定義唯一的自訂 ID。
若你對兩個不同的文字元素使用相同 ID，擷取工具只會擷取第一個，而 Angular 會用它的翻譯取代兩個原始文字元素。

例如，在下列程式碼中，兩個不同的文字元素定義了相同的自訂 ID `myId`：

  ```html
    <h3 i18n="@@myId">Hello</h3>
    <!-- ... -->
    <p i18n="@@myId">Good bye</p>
  ```

下列顯示法文翻譯：

  ```xml
    <trans-unit id="myId" datatype="html">
      <source>Hello</source>
      <target state="new">Bonjour</target>
    </trans-unit>
  ```

兩個元素現在都使用相同的翻譯（`Bonjour`），因為它們定義了相同的自訂 ID：

  ```html
    <h3>Bonjour</h3>
    <!-- ... -->
    <p>Bonjour</p>
  ```
